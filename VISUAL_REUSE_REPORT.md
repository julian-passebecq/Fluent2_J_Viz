# Visual reuse report

## Existing VizForge visual grammars reused

The validation branch preserves the merged V1.2 engine rather than adding chart families for the sake of the consumer test.

VizForge currently provides 15 reusable visual families:

1. time-series evolution
2. animated ranking
3. scatter/bubble evolution
4. dumbbell/before-after
5. KPI contribution
6. Sankey/flow
7. forecast + uncertainty
8. event map
9. analytical table
10. analytical matrix
11. bump/rank evolution
12. histogram/distribution
13. small multiples
14. stacked-area/composition
15. choropleth

The catalog retains 22 original synthetic examples plus four pinned real-data flagship stories. The consumer validation does not add bespoke geometry, D3 code or a one-off renderer.

## Datapass + VizForge composition

Two different visual engines are deliberately composed rather than merged:

- ConceptMotion / Datapass renders the accepted technical source-to-KPI lineage Figure.
- VizForge renders analytical/editorial stories through the external `vizforge.d3` adapter.
- A single Datapass `FigurePlayer` owns hosted analytical playback.
- The lineage Figure remains static while the adjacent VizForge story advances, proving independent renderer ownership.

No D3 geometry is copied into ConceptMotion and no ConceptMotion renderer is recreated inside VizForge.

## Semantic state and motion reuse

VizForge scenes remain deterministic absolute states. Motion is generated by stable keyed D3 joins between those states rather than authored pixel trajectories.

The release suite already verifies:

- stable DOM identity during animated ranking;
- a measured intermediate coordinate between start and end values;
- interrupted transition/reset settling deterministically;
- reduced motion using the same semantic state without interpolation;
- no autoplay by default;
- cross-family story changes using consistent entity identities and colors where the visual grammar permits it.

The V1.2 flagship phone regression also proved that resize/reflow can interrupt a real D3 transition. The fix was made in VizForge's renderer lifecycle rather than hidden by weakening the motion test.

## Consumer-specific presentation added in this pass

The consumer workbench now makes each discrete StorySpec scene self-explanatory above the figure:

- `WHAT HAPPENS IN THIS STEP` displays the authored scene caption.
- `LOOK HERE` displays the authored annotation text for the current scene when present.
- On narrow screens, existing `shortText` annotation variants are used when available.

This is presentation reuse of existing semantic content. No duplicate lesson text, generated interpretation or new StorySpec field is introduced.

## Bespoke visualization code in this pass

None.

The only code added for the consumer proof is presentation CSS/React around existing captions and annotations, deployment configuration, tests and evidence reports.

## Current visual gaps worth observing in the deployed consumer

- Datapass lineage minimum width remains awkward at 390px and currently uses a horizontal readable viewport.
- FigurePlayer hosted cadence does not consume VizForge `intervalMs`.
- External-renderer export is consumer-owned.
- Dense maps, collision-heavy labels, large-graph layout and full scrollytelling remain intentionally outside V1.2.
- Power BI packaging remains deferred; future integration must adapt DataView into the same canonical VizForge specs and reuse the same D3 renderer.
